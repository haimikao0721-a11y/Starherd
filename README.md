### 左右键到底差在哪（这是最容易搞混的地方）

| | 左键 | 右键 |
|---|---|---|
| 作用 | **吸引**：把货舱拉向引力井 | **排斥**：把货舱推离引力井 |
| 场线形状 | 金色实线，**6 个向内指的雪佛龙**，内圈实线 | 青色，**6 个向外指的雪佛龙**，外圈虚线 |
| 井旁徽标 | 「吸附」（暖金） | 「排斥」（冷青） |
| 典型用途 | 减速、降低轨道、把货舱拽进环 | 紧急避让、防撞、接近环时微调、把货舱推开 |

两者**只共享"井跟随鼠标"这一件事**，力的方向严格相反（实测：同一位置 `|a_排斥|/|a_吸引| = 0.9992`，
内积 `≈ −|a|²`，见 `src/sim/physics.ts:47` 的 `if (repel) mag = -mag`）。
视觉上曾经分不清——因为旧版斥力色取自章节调色板的 `orbit`，而**第 3 章 well/orbit 都是蓝色、第 4 章都是紫色**，
两态同色。现在改用与调色板无关的**固定语义色 + 方向雪佛龙 + 徽标**，任何章节都一眼可辨
（对比图：[第 3 章吸引](docs/screenshots/field_attract_loop3.png) / [第 3 章排斥](docs/screenshots/field_repel_loop3.png)）。
演示动画第 2/3 幕还会把两种状态并排演给你看。

### 3.0.00 背景音乐：全部程序化合成 + EXE 内可下载

**音乐不是素材，是合成的**：`python/music_gen.py` 只产出**谱面 JSON**（音符/拍号/调式/段落），
运行时由 `src/audio/music.ts` 用 WebAudio **实时合成**（振荡器 + 滤波器 + 包络）。因此没有任何
第三方音频文件、没有版权问题，EXE 里也不含 mp3/wav。

| 曲名 | 用途 | BPM | 调式 | 时长 |
|---|---|---|---|---|
| **牧星者** Shepherd of Stars | 主菜单 | 84 | C mixolydian | 45.7s |
| **首次接触** First Contact | 第 1 章 | 96 | A aeolian | 40.0s |
| **碎屑带** Debris Belt | 第 2 章 | 110 | D dorian | 34.9s |
| **双星共振** Binary Resonance | 第 3 章 | 116 | G lydian | 33.1s |
| **深渊视界** Abyss Horizon | 第 4 章 | 92 | E phrygian | 41.7s |

每章一个调式（忧郁 → 开阔 → 明亮 → 压迫），音符带 `intensity` 阈值 → **强度越高声部越多**
（`lead` 主音只在强度 > 0.7 出现）；另有 17 个音效同样是程序化合成。

**下载功能（仅 EXE / 网页模式）**：`python/music_render.py` 用纯标准库把**同一份谱面**离线渲染成
16bit/44.1kHz WAV（峰值归一化 + 淡出 + 近似 TS 合成器的声部包络），宿主提供
`GET /api/music`（曲目表）与 `GET /api/music/<id>.wav`（按需渲染 + 临时目录缓存）。
游戏内入口在**暂停页 →「背景音乐下载 / SOUNDTRACK」**。

> **为什么离线单文件版没有这个选项**：该版本跑在 `file://` 下、没有宿主进程，
> `isOffline === true` 时游戏**既不请求也不渲染**该区块（已验证：离线包打开后暂停页没有下载区块）。
> 这正是需求要求的"只在 exe 里能下载，html 里没有这个选项"。

### 3.0.0 玩家反馈的三项修复（性能 / 流程 / 运气）

| 反馈 | 根因 | 修复 | 实测 |
|---|---|---|---|
| **"画面只有 30Hz"** | `quality.targetFps` **一直存着却没有任何代码使用它**——渲染成本超过帧预算后没有任何降级机制，于是长期停在 ~30fps | **自适应渲染分辨率**：以 `targetFps` 为预算（滞后带 1.12/0.72），超标就降 `rs`（0.62 → 最低 0.35）、有余量再回升；物理仍是 120Hz 固定步长，**只有渲染分辨率随帧预算伸缩**，因此 60Hz 与 120Hz 屏都能落在各自目标上 | p50 帧时 **15.3~15.8ms（≈60~65fps）**，从原来的 21~24ms 提升；`verify_ui` 帧率项由"反复擦线"变为稳定 PASS |
| **"每三关要自己手点下一关"** | 章末 `nextLevel()` 切到 chapter 画面后**只显示卡片、等玩家点击**，节奏被打断 | **自动续章**：章末卡片展示 3.5 秒后自动进入下一关（点一下可立刻跳过，带状态守卫避免重复推进） | 实测 L1-3 通关 → 等 4.2 秒 → 自动进入 **L2-1**（无需手点） |
| **"运气性太重"** | 本质是**只能在相位窗口前干等**：轨道相位不齐就没法对接，玩家没有推进手段 | **时间加速（T 键 1×→2×→4×）**：把"等轨道转到合适位置"从被动等待变成玩家可主动推进的过程；慢动作（空格）优先 | 实测 T 键循环 `2× → 4× → 1×`，`world.timeScale` 同步 |
| **"引力井飞出地图，没有重开的内容"** | ① 目标点原先只钳到 `bounds×1.1`，鼠标顶在画面边缘就能把飞船开出去；② 井有惯性，**目标点钳住不等于船不出去**（实测冲到 **17.19 RU**，而 bounds=8）；③ 越界后关卡既不提示也不判失败 | **三层保护**：① 目标点钳到 `bounds`；② 物理层加**硬边界**（`wellConstraint`：越界投影回边界并去掉向外径向速度，与恒星光球层同一层）；③ HUD 常驻提示"已脱离作业区 —— 鼠标移回中心召回，或按 R 重试"+ 自动召回 toast | 同样操作下井位置 **17.19 → 8.16 RU** ✓；暂停菜单本就有"重试本关"，但**关卡必须主动告诉玩家**，不能靠玩家自己想到 |

**层级轨道（卫星 / 绕行星的空间站）**：`OrbitSpec.parent` 指定父天体后，状态 = 父天体状态 +
**以父天体 μ 解算**的相对开普勒轨道（拼锥近似，真实任务设计所用方法）。因此卫星周期、速度、
Hill 球全是真值；货舱会被卫星引力**真实扰动**（`src/sim/world.ts: placeOrbit`）。

**关卡校验器（`python python/levelgen.py --validate`）** 除原有几何/撕裂/ISCO 检查外，另含三类
**实测踩坑后补上**的判据：

| 判据 | 拦住的错误 |
|---|---|
| 非退化：货舱起点距站 > 1.5×环半径、Δa 与相位不能同时趋零 | 货舱生在对接环里 → 自动化报 0.0 TU "通关"（假通过） |
| **自动对接余量**：货舱近星点与站轨道半径之差 > 1.55×对接环半径 | 两者轨道几乎相切 → **无人操作时相位一对齐就自动对接**（实测 L2-3 开场 3 秒自动送达；复查发现 L3-1/L3-2/L4-2/L4-3 **四个原生关卡同样存在**，L4-3 的间距只有 0.023 而环半径 0.080） |
| **货舱互撞**：同关两个货舱的**真实历元距离** > 4×货舱半径 | 同轨道同相位 → 出生即互相撞毁（实测 L4-2/L4-3 报 0.0 TU 损毁 2）。判据必须算真实历元距离：早期写成"同 a 就取半径和"会让 6 个关卡全部误报 |
| **出生净空**：货舱出生点距任何恒星/行星/黑洞 > 天体半径 + 3×货舱半径 + 0.01 | 开局即撞击天体（实测 L3-3 出生 0.12 TU"撞击行星"，关卡直接不可通关） |
| **轨道走廊净空**：货舱 [近星点, 远星点] 不得与其它天体轨道区间重叠 | 出生点没问题但**轨道穿过碎石带/行星轨道**（L3-3 的真正病因；修法是给走廊留出柯克伍德式空隙） |
| 层级稳定：顺行卫星轨道 < 0.5 × **父天体** Hill 球 | 卫星被放到 Hill 球外（根本不会被束缚） |
| 多星稳定：Mardling & Aarseth (2001) 判据 + **内双星周期 ≥ 4 TU** | 层级三星不稳定 / 引力场时变快到玩法上不可操作 |
| 撕裂/中心天体：用**实际环绕天体**的 μ 算撕裂半径与引力主导 | 绕行星的空间站被按恒星 μ 误判为"半径过小、进站会被撕碎" |

> 上面两条加粗判据是**卫星系统关卡暴露出来的**：为了做"站绕行星"，先修好了 HUD 与校验器对层级轨道的理解，
> 顺带查出 6 个关卡（含 4 个原生关）存在"自动对接"漏洞——即关卡可以**自己通关**。这类缺陷不会崩、
> 不会报错，只会让关卡失去意义，因此必须由判据而不是靠肉眼发现。

**可行性证据（`python python/levelgen.py --analyze`）**：每一关打印一条构造性结论——

```
[可行性] 霍曼解: 货舱机动 Δv = 0.1080 RU/TU（场强上限 1.1 可在 0.098 TU 内提供）
         · 转移时间 4.39 TU · 时限 56.2 TU · 圆化前相对速度 0.108 vs 窗口 0.65 → 可行 ✓
```

**当前 12 关全部"可行 ✓"**。注意区分两个物理量：霍曼 Δv 是**货舱轨道机动**的速度增量，
而飞船的 Δv 预算是**投影器自身的推进积分**（40+6×难度）——单位相同、含义不同，不能直接比大小；
可核验的判据是"场强上限能否在时限内提供该 Δv"与"时限 ≥ 1.25×霍曼转移时间"。

**自动驾驶的定位**：它是**能力下限探针**（刻意做弱），不是难度标尺。当前 12 关里它能通关 **4 关**
（L1-1 / L1-3 / L2-2 / **L2-3 卫星走廊 5.9 TU**），其余关卡多为碰撞损毁或超时——
这**不代表关卡无解**（可行性判据已构造性证明 12/12 有解），只说明这个启发式驾驶员还不够格。
绝不为迁就它而下调关卡难度。

**探针本身的五次实质改进**（都是 trace 出来的，不是猜）：

### 多循环与生命周期
- **渲染循环**（rAF，带 alpha 插值）、**物理循环**（120 Hz 固定步长，防死亡螺旋）、**音频调度循环**
  （25 ms lookahead）、**遥测循环**（1 Hz）、**后台降级**（`document.hidden` 暂停物理与音频）、
  **自检循环**（`?autotest=1` 全自动跑完一关并回报）。
- **游戏生命周期**：`BOOT → PRELOAD → ATTRACT(演示) → MENU → BRIEFING → PLAY ⇄ PAUSE → DEBRIEF →
  CHAPTER → VICTORY/DEFEAT → SHUTDOWN`，每个场景有进入/退出钩子与淡入淡出转场。
- **进程生命周期**：生成/校验素材 → 起服务 → 选端口（占用自动 +1）→ 开窗口 → 心跳 → 存档 → 关窗即回收端口与子进程。
- **进程级"多循环"**：12 关 × 4 章，每章有独立的调色板与配乐，通关解锁下一章。

## 6. 计分

`总分 = 1000 × (0.35·时间 + 0.30·燃料 + 0.20·物理保真度 + 0.15·货舱存活) × 难度系数 + 连击奖励`

- **时间**：满分基准 = `2.5 × par_time`（par_time 是物理最短时间，人类无法贴着它完成）
- **燃料**：飞船 Δv 预算的 55% 视为优秀飞行；**燃料不是魔法**——移动引力井所需的推力即消耗，由火箭方程记账
- **物理保真度**：Python 独立复算主天体子系统的 `ΔE/E`、`ΔL/L` 并评级（S/A/B/C = 1.0/0.85/0.7/0.5）
- **存活**：按送达货舱的完整度加权（软对接满分、硬对接扣分）
- 评级：S ≥900、A ≥780、B ≥640、C ≥480

三种对接结果：**软对接**（环内且速度达标，满分+连击）、**硬对接**（1.8 倍泊位包络内，货舱受损）、
**撞环弹开**（速度超限，受损并被弹回）。全部由真实相对速度判定。

## 7. 性能

实测（1600×900，**本机浏览器无 GPU 加速的软件光栅化环境**，属最坏情况）：

| 画质 | fps | 帧耗时 p50/p95 | 渲染 | 逻辑 | HUD |
|---|---|---|---|---|---|
| high（默认） | 31.6 | 14.6 / 15.5 ms | 14.1 ms | 0.03 ms | 0.9 ms |
| mid | 28.6 | 15.9 / 18.6 ms | 15.4 ms | — | 1.1 ms |
| low | 44.5 | 11.4 / 12.4 ms | 10.6 ms | — | 0.9 ms |

- 有 GPU 加速的机器上会显著更高（Canvas2D 合成走 GPU 快路径，实测同一操作 0.08ms vs 14ms）。
- **自适应画质守卫**：帧耗时连续超标会自动降档（high→mid→low 并关场线）并提示，保证"掉画质不掉帧"。
- 优化过程中定位并修掉的两个真实瓶颈（均有实测数据支撑）：
  1. 背景层按**全分辨率**做大画布加性合成 → 单次 51ms；改为 1/3 分辨率烘焙 + 放大贴回（GPU 快路径）。
  2. 全分辨率场景 → 可见画布的 1:1 合成走 CPU 路径 → 30.8ms；改为按 `renderScale` 子分辨率渲染 + 放大合成。
  合计 renderMs **113 → 14.1**（8 倍）。

## 10. 已知限制

## 10. 难度与新手体验

设计原则（来自实测反馈）：**整体可以有难度，但第一关必须"试几次就能理解并通关"**，否则挫败感会盖过学习曲线。

### 10.0 教学关（L1-1）的可通关性

| 项目 | 调整前 | 现在 | 为什么 |
|---|---|---|---|
| 货舱轨道 a | 1.679（离站 0.58 RU） | **1.24（离站 0.14 RU）** | 原来要求新手做一次完整霍曼转移（两次点火），现在是"轻推一下轨道就下沉" |
| 对接环半径 | 0.14 RU | **0.24 RU** | 0.14 的环要求接近零的横向误差，对第一次玩的人过于苛刻 |
| 对接限速 v_max | 0.35 | **0.60** | 0.35 需要近乎共速，实测新手几乎必然"撞环弹开" |
| 潮汐撕裂 | 全程生效 | **第 3 章起才启用** | 撕裂是"高级机制"（见 §3 表），却在第 1 章无任何预警地即死；已改为按关卡声明或章节开启 |
| 关卡提示 | 写死旧几何 | 按当前数据生成 | 提示里的"1.46 vs 1.10"曾是硬编码，改几何后会误导 |

客观下限：把**自动驾驶**当作"能力下限探针"跑 `node tools/simtest.mjs assets/data/systems.json 120 --level=L1-1`
→ 现在 **成功**（送达 1、损毁 0、最小相对速度 0.194）。自动驾驶是本项目里最笨的"玩家"，
它能过，人一定能过。

### 10.0.1 失败要能被理解（不是只给一个"失败"）

- **损失原因即时提示**：货舱损毁时立刻弹出原因（`坠入恒星` / `越过视界` / `撞击小行星` / `潮汐撕裂`）；
- **撞星预警**：HUD 顶部实时算每个货舱的**近星点** `r_peri = a(1−e)`，低于安全线时闪烁警告
  "⚠ 货舱近星点 X.XX RU < 安全线 —— 再拉下去它会撞进恒星"——在损失发生**之前**给出可反应的信息；
- **一键重试**：`R` 立刻重开本关；结算页也有"重试"按钮。

### 10.1 鼠标 → 引力井：曾经整条失效（已修复）

`frame()` 里 `driveControl()` 读的是 `input.snapshot.wx/wy`，而这两个字段只有 `input.update(view)`
会写——**而这一行从来没被调用过**。后果：`wx/wy` 恒为 `(0,0)`，玩家的鼠标实际控制不了引力井，
井每帧都被指向世界原点（恒星中心），于是必然卡在恒星附近、怎么点都没反应。

这个 bug 能活到最后，是因为**所有自动化测试都绕过了人类输入路径**：自检与菜单演示走自动驾驶
（直接写 `well.tx/ty`），UI 测试只点 DOM 按钮。现在 `tools/verify_ui.py` 增加了 `control` 阶段，
逐步把鼠标移到 4 个位置并断言"引力井目标点 == 鼠标世界坐标"，这类问题不会再静默回归。

### 10.2 恒星光球层：任何局面都能脱身（死局已消除）

牧星者号的推力上限只有 `A_MAX = 3.0 RU/TU²`，而恒星引力 `μ/(r²+ε²)^{3/2}·r` 在 r=0.02 处高达 884——
**两者交叉点在 r≈0.57 RU，以内飞船根本拉不动**。所以"把井拖进恒星"曾是不可逆的死局。现在三层防护：

1. **控制层**：鼠标目标点被投影到 `STAR_KEEPOUT`（恒星半径 +0.22 RU）之外——从构造上无法把井设进恒星；
2. **光球层硬边界**（`step.ts: wellConstraint`）：位置被硬性夹回边界并去掉撞向恒星的速度分量，像真实碰撞面；
3. **护盾带**（`STAR_SHIELD`，半径 +0.62 RU）：带内按距离平滑抵消恒星引力，让 3.0 的推力重新拥有控制权，
   于是井永远能被拖回（实测：强行塞进去后仍可拖回 3.87 RU 外）。

### 10.3 实体名牌与目标指示（解决"我看不懂"）

- **画面内名牌**：恒星（引力源）/ 空间站 · 对接环 ← 目标 / 货舱N ← 送它进环 / 牧星者号（引力井）；
- **顶部目标条**：`目标：把货舱送进对接环（相对速度 < v_max）`，第 1 关首次游玩时自动下移避开引导条；
- **屏幕外箭头**：目标离开视野时，在屏幕边缘画脉动箭头 + 直线距离（RU）；
- **左右键语义色**：吸引＝暖金+向内雪佛龙+「吸附」，排斥＝冷青+向外雪佛龙+「排斥」（与章节调色板无关）。

## 11. 启动故障排查（页面卡在加载界面怎么办）

启动链现在有三层保护，任何一环出问题都会**明确告诉你卡在哪**，而不是一直转圈：

1. **启动异常面板**：启动期任何异常（渲染器/菜单/HUD 构造失败、未处理的 Promise 拒绝）都会把错误堆栈直接画在启动面板上。
2. **启动看门狗**：30 秒仍未进入主菜单（例如某个 `await` 永远 pending——`AudioContext.resume()` 在浏览器自动播放策略下正是如此）
   会弹出"启动超时 + 已完成的阶段链"，精确定位到哪一步。
3. **宿主回执**：页面每次启动都会向宿主写一份回执，可直接读：
   ```powershell
   Get-Content "$env:LOCALAPPDATA\LagrangeCourier\selftest.json" -Raw
   ```
   成功：`{"ok":true,"boot_ok":true,"phases":[...],"assets":"36/36","levels":12,...}`
   失败：`{"ok":false,"boot_failure":true,"error":"...","phases":[...]}`

| 现象 | 原因 | 处理 |
|---|---|---|
| 卡在加载界面 | 旧构建（旧版启动期异常不显示） | **用最新构建**：重新双击 `dist_exe\Starherd.exe` 或 `启动网页版.bat` |
| 报"无法启动" | 任务控制中心没在跑 | `启动网页版.bat`；或确认 `python python/mission_control.py --web` 在运行 |
| EXE 空白/无响应 | 上一次的 EXE 或 WebView2 子进程仍占着端口 | 任务管理器结束所有 `Starherd.exe` 与 `msedgewebview2.exe` 后重开 |
| 浏览器连不上 | 停留在上个会话的旧标签（宿主端口已变） | 关掉旧标签，从 `启动网页版.bat` 重新进入 |
| 想确认服务活着 | — | 打开 `http://127.0.0.1:8760/api/health`，应返回 `{"ok":true,...}` |
| 点「退出」没反应 | **已修复**：旧版只停掉宿主服务、没有销毁窗口，窗口留下来变成僵尸页 | 用最新构建。现在的行为：窗口版会销毁窗口并让进程干净退出；网页版会显示"已退出任务控制中心"覆盖层（浏览器规范不允许脚本关闭标签页，需手动关闭） |

若仍失败，把 `%LOCALAPPDATA%\Starherd\selftest.json` 的内容发出来即可定位。
